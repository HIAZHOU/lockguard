# 锁车卫士 v0.3

安卓本地锁车确认助手。定位速度、步频与时间联合判断；不能读取共享单车车锁或订单状态。首页保留状态、计时和操作；运行设置和诊断在「更多」。

## 本轮修复

- **慢骑识别**：约 8 km/h 以上连续 8 秒；约 6.1–8 km/h 连续 30 秒且无明显步频。计时从连续证据起点回溯；首次定位延迟另计。
- **异常速度保护**：网络点不参与速度判定，不与 GPS 混算两点速度。76 km/h 等异常值被拒绝，不结束未确认会话；恢复骑行需连续证据。
- **待机省电**：确认锁车后关闭持续 GPS；显著运动传感器触发短时检测。无运动唤醒能力时改为间歇窗口。停车等待也停止持续定位。
- **减少长时间唤醒**：首次停车提醒后释放持续 CPU 唤醒锁，通过时钟与系统非精确唤醒闹钟继续提醒。Android 12+ 的短时定位请求带有效期。
- **多品牌引导**：统一「一键检查与设置」，只显示本机建议。识别 OPPO、vivo、Xiaomi、realme、iQOO、Redmi、HONOR、nubia 等品牌，未知品牌使用通用入口。
- **诊断**：更多页支持分享文本日志，包含权限与机型、不含坐标；ADB 的 `LockGuard` 标签可实时查看 GPS 开关与识别原因。

「一键」指统一检查/跳转，不代表替用户授权或自动修改厂商私有设置。适配指南并不等于所有品牌/系统版本已逐机实测。

## 已保留的能力

- 减速/步行后约 2 分钟提醒，不要求离开 80 米；适合停车后只走 5–10 米的场景。
- 定位断流不会让已停下状态一直卡住；已有骑行会话但缺少可靠定位时请求核实。
- 我已锁车结束会话；暂缓 10 分钟后仍未确认可再次提醒。
- 从系统设置返回立即重读标准权限；厂商私有开关标为需手动确认。
- 单调时钟计时，业务逻辑在主线程串行处理。

## 边界

这些是启发式参数，需要真实路测校准；快走、跑步、低速乘车可能误触发，慢骑或无可靠定位仍可能漏检。未授权身体活动会减少可用证据。后台被强停/杀进程或手机重启仍可能丢失内存会话与日志。

静止待机省电与唤醒速度有取舍：无可用运动唤醒传感器的设备、深度休眠下的非精确闹钟可能增加检测和后续升级延迟。锁车后 90 秒内冷却可能延迟再次自动识别。没有实测耗电下降百分比，也没有完整 IMU 分类模型。

计时包含停车等待，不是平台计费时间。还车成功以平台确认为准。App 未声明 INTERNET；自身不上传定位，系统定位提供者可能使用系统自身服务。

## 安装、真机调试和省电验收

参见根目录 [v0.3 调试与省电说明](../锁车卫士-v0.3-调试与省电说明.md)，包含 USB / 无线调试、截图问题分析、测试顺序、品牌适配边界和 Git 恢复方法。

```powershell
.\tools\debug_device.ps1 -Live
```

需要先连接手机并授权 USB 调试。诊断文件写入根目录 `diagnostics`，不会加入 Git。

## 构建

```powershell
.\tools\build_apk.ps1
```

本机脚本使用 JDK 17、Gradle 8.9、Android SDK 35 和 D:\GradleHome 缓存。默认离线；缓存缺失时加 `-Online`。脚本从当前源码建立临时英文路径副本，避开 Windows JDK 17 的中文 classpath 问题，测试和 Lint 通过后拷回 APK 与报告。

- APK：`app/build/outputs/apk/debug/app-debug.apk`
- JUnit：`app/build/reports/tests/testDebugUnitTest/index.html`
- Lint：`app/build/reports/lint-results-debug.html`

测试直接调用实际 Kotlin 实现，包括慢骑/快走、原地/5–10 米提醒、76 km/h 截图回放、同源速度过滤、GPS 窗口、权限引导品牌映射等。当前没有连接真机，构建和合成测试不能代替息屏路测或实际耗电测量。

旧版行为可通过 Git 标签 `v0.2-baseline` 查阅；历史技术方案不是 v0.3 的行为规范。
