# 锁车卫士 v0.2

安卓本地锁车确认助手。首页只保留状态、计时和当前动作；权限、定位诊断与日志在「更多」。

## 本次修复

- 使用 Android `LocationManager` 的 GPS / 网络定位，不再依赖 Google Play 服务。
- 定位请求间隔为 5 秒，不批量等待。实际交付频率仍由设备和系统决定。
- 约 8–25 km/h 的速度持续 15 秒才自动开始，过滤单点突刺；计时回溯到该连续区间起点。
- 正确保留定位的 0 速度。无速度时仅在两点位移超过定位误差后推导，不把未知速度伪装成静止。
- 已有骑行会话减速/步行后，30 秒进入等待确认状态，约 2 分钟触发锁车确认提醒。无需离开 80 米。
- 定时器独立驱动停车确认和提醒升级，后续 GPS 断流不会让「已停下」永久卡住。
- 骑行中没有可靠定位持续 3 分钟，发送一次「定位中断，请核实锁车」提示，不宣称已停车。
- 可选原生计步检测器：20 秒内至少 6 步，且最近 15 秒无骑行速度证据时，辅助开始停车计时。
- 重新骑走会撤回提醒；确认已锁车会清理本次状态；暂缓到期后可再次提醒，新骑行不继承旧暂缓。
- 从权限弹窗或系统设置返回后刷新权限，同时尝试恢复服务。小米私有开关明确标为需手动核对。
- 所有业务回调在主线程串行处理，计时使用单调时钟，不受修改系统时间影响。
- 会话进行中持有有超时的 CPU 唤醒锁，避免普通休眠只冻结提醒计时；待机释放。不能绕过强行停止、厂商杀进程或系统全部限制。

## 实际能力与边界

当前实现是「定位速度 + 原生计步辅助 + 时间兜底」，没有完整的加速度计/陀螺仪骑行分类模型，也没有读取共享单车车锁或订单状态。

- 自动识别需要可靠定位与速度证据。很慢的骑行、地下车库或一直没有有效定位时仍可能漏检，保留手动开始作为补充。
- 速度只能筛选疑似骑行，无法完全区分跑步、低速汽车、电动车、自行车。当前参数需要校园路测校准。
- 骑行后原地久等、推车或持续很慢地骑行超过约 2 分钟，也可能提醒；这是优先避免 5–10 米场景漏报的取舍。可点暂缓。
- 地理距离只能辅助提前提醒，距离阈值仍为 80 米并扣除两点精度误差。不会尝试用不可靠的 5 米 GPS 围栏判断车锁。
- 页面计时为「本次已开始」，包含停车等待，不是纯骑行运动时长，也不是平台准确账单时长。
- 确认还车以共享单车平台显示为准。即使收到提醒，也不能据此认定车锁未关闭。
- 服务被强行停止、进程被杀、手机重启后，当前会话仍可能丢失；本版没有持久化骑行轨迹或恢复完整会话。
- 每 5 秒请求定位比旧版待机每 60 秒更耗电。需实测全天耗电，再决定引入低功耗运动唤醒。
- App 未声明 INTERNET；自身不上传定位。系统定位提供者可能使用系统自身的定位服务。

## 安装与检查

1. 用新 APK 覆盖安装旧版，打开「更多 → 申请基础权限」。
2. 开启精确定位、手机定位、通知及提醒通知通道；身体活动为可选辅助权限。
3. 为后台恢复建议设为始终允许定位。小米另需核对无限制省电、自启动、锁屏通知与横幅。
4. 返回应用后权限标签立即重读；厂商私有设置不伪装为已检测。
5. 在室外骑行，观察「更多 → 运行日志」是否有 GPS、速度、精度及进入骑行记录。

## 真机验收

| 场景 | 预期 |
|---|---|
| 室外正常骑行，手机放口袋 | 获得连续合格速度后自动进入骑行并计时 |
| 停车后原地等待 | 从减速被检测到开始约 2 分钟提醒确认 |
| 停车后走 5 米 / 10 米进楼 | 不依赖距离跨过阈值，定时或计步路径继续提醒 |
| 已显示停下，随后关闭定位 | 定时器继续推进停车确认和提醒 |
| 骑行态直接失去定位，无停下证据 | 约 3 分钟后提示定位中断、请核实 |
| 红灯 45 秒 / 90 秒后继续骑行 | 不到 2 分钟，不发停车超时提醒；恢复骑行 |
| 点我已锁车 | 本次计时结束，提醒被撤销 |
| 点暂缓 | 10 分钟内静默，到期仍未确认可再次提醒 |
| 设置中开启权限后返回 | 不需重启应用，权限状态重读 |
| 息屏后重复近距离停车测试 | 检查实际通知送达时间、振动和系统后台限制 |

当前开发环境没有连接手机；单元测试、APK 构建和静态检查不等于真机路测通过。

## 构建与验证

本机工具链：JDK 17、Gradle 8.9、Android SDK 35。构建缓存位于 D:\GradleHome。

```powershell
.\tools\build_apk.ps1
```

脚本运行实际 Kotlin JUnit、生成 debug APK、执行 Android Lint。默认离线，缓存不全时用 `-Online`。为避开 Windows JDK 17 在中文 classpath 下无法加载测试类的问题，脚本将当前源码复制到独立英文临时目录构建，验证通过后把 APK 和报告拷回项目；保留临时目录便于诊断。

产物：`app/build/outputs/apk/debug/app-debug.apk`。
测试报告：`app/build/reports/tests/testDebugUnitTest/index.html`。
Lint 报告：`app/build/reports/lint-results-debug.html`。

`tools/verify_state_machine.py` 已改为调用实际 Kotlin 测试，不再验证一套与产品代码分离的 Python 模型。

## 主要代码

- `core/RideStateMachine.kt`：识别、计时、提醒状态机，无 Android 依赖。
- `core/RideModels.kt`：阈值与事件。
- `service/RideMonitorService.kt`：原生定位、计步、前台服务、独立时钟。
- `ui/MainActivity.kt`：简洁首页、更多页、权限刷新。
- `notify/AlertDispatcher.kt`：按提醒原因生成通知，不把推测写成已确认事实。

详细技术评估见项目根目录的「锁车卫士-v0.2-问题分析与方案.md」。旧技术方案文档描述 v0.1 历史设计，不能作为 v0.2 行为规范。
